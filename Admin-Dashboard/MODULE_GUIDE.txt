DropLock Admin Dashboard — Module Guide
======================================

This note explains what each module currently does and suggests improvements while keeping the same RTDB structure.

Core App Modules
----------------
1) app.py
   - Main Streamlit entrypoint.
   - Handles login/session, role-based navigation, and all UI pages:
     * Overview
     * Sector Config
     * Operations
     * Alerts Center
     * Admin Management (superAdmin)
     * Activity Feed
     * Modules & Ideas

2) admin_init.py
   - Bootstraps Firebase Admin SDK.
   - Verifies ID tokens from sign-in flow.

3) authentication.py
   - Performs admin login (email + password) against Firebase Auth endpoint.

4) admin_ops.py
   - Reads admin profile from /profiles/{uid}.
   - Enforces role/sector permissions.

Locker & Sector Domain
----------------------
5) locker_repo.py
   - Data-access layer for lockers and sectors:
     * read all sectors
     * read/update locker state
     * create/delete locker
     * append locker events
     * update sector config

6) locker_actions.py
   - High-level admin operations for lockers.
   - Executes guarded state changes and OPEN requests with audit hooks.

7) metrics.py
   - Builds LockerView objects from raw locker data.
   - Derives offline status from heartbeat timestamps.
   - Aggregates metrics for dashboard cards.

Alerts & Notifications
----------------------
8) alert_service.py
   - Reads/writes /alerts records.
   - Creates deduplicated alerts for tamper/offline scenarios.
   - Updates alert status (OPEN -> ACKED -> CLOSED).
   - Optionally sends alert email via SMTP service.

9) smtp_service.py
   - SMTP wrapper for outbound alert emails.
   - Uses configured credentials and destination address.

Audit & Commands
----------------
10) commands.py
    - Writes OPEN commands under /adminCommands/{sector}/{locker}/{pushId}.

11) booking_audit.py
    - Appends booking event history under /bookingEvents/{bookingId}/{pushId}.

Provisioning
------------
12) user_provisioning.py
    - Super admin tooling for:
      * create admin users
      * list profiles
      * disable/reactivate admins
      * reset temporary password

13) admin_init.py / bootstrap_owner.py / admin_init helpers
    - Initial bootstrap scripts and setup helpers to seed owner/superAdmin paths.

UI Helpers
----------
14) ui_components.py
    - Shared visual rendering helpers:
      * metric cards
      * state/timestamp formatting
      * tamper badge
      * global style and hero banners

Suggested Improvements (Next Iteration)
----------------------------------------
A) UX / Frontend
   - Add chart widgets (timeseries for tamper/offline trends).
   - Add dark/light theme toggle in sidebar.
   - Add sticky action toolbar for bulk locker operations.
   - Replace temporary stock image with branded visual assets.

B) Reliability
   - Add retry + user-friendly errors for transient Firebase failures.
   - Add heartbeat anomaly detector (sudden missing pings by sector).
   - Add server-side pagination for very large alert feeds.

C) Security
   - Add optional 2FA for superAdmin logins.
   - Add audit trail export for admin profile mutations.
   - Add stricter password policy checks in provisioning form.

D) Operations
   - Add bulk state change endpoint (MAINTENANCE for selected lockers).
   - Add command delivery status (queued/sent/acked by IoT edge).
   - Add scheduled report emails with daily sector summaries.

E) Quality
   - Add unit tests for metrics derivations and role checks.
   - Add integration test that mocks RTDB reads/writes.
   - Add typed schemas (pydantic/dataclasses) for alert/locker payloads.
